# Relecture finale — modules 04, 05 et 06 — 2026-10-24

## Résumé

- **Contenu relu** : 17 leçons (6 + 5 + 6), avec leurs quiz (soit 88 questions), et les 3 examens (42 questions). J'ai tout lu dans l'ordre du parcours, en me mettant à la place d'un débutant de 13-16 ans.
- **Volume** : environ 50 corrections dans 20 fichiers. Aucun fait, chiffre, nom d'API ni code Luau n'a été modifié. Seuls deux ajouts reposent sur des faits, tous deux sourcés : les places d'un même jeu partagent les mêmes DataStores, et la procédure de création d'un attribut dans Studio. Deux sources officielles ont été ajoutées en conséquence.
- **Types de corrections** :
  1. **Pas à pas manquants (module 04 surtout)** : où créer chaque objet (bouton ⊕, type, nom exact), dans quel ordre, comment tester (vue Client/Server, chemin dans l'Explorer, Command Bar). Ajouts aussi des scripts à supprimer, de l'ID à remplacer et du contenu par défaut d'un ModuleScript à effacer.
  2. **Clarté** : paragraphes trop denses découpés (accès Studio aux DataStores, early testers, Creator Rewards), une formulation imprécise rectifiée (« au centre » au lieu de « en haut »), et une ligne manquante ajoutée dans un schéma de hiérarchie.
  3. **Cohérence entre leçons** : le bouton « Passer l'étape » était annoncé « de la leçon 3 », mais il n'y était jamais créé. Les noms des scripts de test ont été fixés (`TestInventaire`, `SuiviPlaytest`). Le pluriel « obbys » est désormais uniforme dans mes modules. Le titre de l'examen du module 5 a été aligné sur ceux des modules 4 et 6.
  4. **Langue et typographie** : virgules qui servaient de deux-points dans les explications de quiz, un double deux-points dans une même phrase, une tournure incorrecte (« souvent appelé courbe… »), un mot mal choisi (« exhibe »). Les apostrophes, les guillemets et les espaces avant `: ; ! ?` ont été vérifiés par script : ils sont cohérents.
  5. **Ton responsable dans le module 06** : un encadré « Tu es mineur ? » a été ajouté. La leçon 2 demande désormais l'accord d'un parent avant tout achat réel de test et précise que ce test est facultatif. Les offres de bienvenue sont recadrées (honnêtes, sans pression).
- **Quiz et examens** : les numéros de ligne de chaque `trouve-le-bug` ont été recomptés (21 extraits) et tous sont justes. Chaque bonne réponse se trouve dans la leçon. Je n'ai relevé aucun piège injuste.
- **Build** : `bash scripts/build-verrou.sh` se termine avec le code 0. J'ai aussi vérifié le rendu HTML des encadrés et des listes imbriquées que j'ai ajoutés.

## Points signalés non corrigés

1. **Command Bar en vue client** (04.03, 06.03) : la leçon suppose qu'en Play solo, la Command Bar exécute le code dans le contexte de la vue choisie (Client/Server). C'est le comportement de Studio que je connais, mais je ne l'ai pas retrouvé dans une page officielle. À confirmer dans Studio, ou à remplacer par un petit LocalScript de test.
2. **« Publish As » vers un nouveau jeu** (04.02, encadré ajouté) : la page officielle décrit **File › Publish As** pour ajouter un place à un jeu ou écraser le place de départ. Le choix « créer un nouveau jeu » dans la fenêtre *Publish Experience* n'y est pas décrit explicitement. Le partage des DataStores entre les places d'un jeu, lui, est bien sourcé (« Data stores are consistent per game »). À vérifier visuellement dans Studio.
3. **Vocabulaire Roblox en transition** : la documentation remplace progressivement « experience » par « game » (la page « Publish experiences and places » s'appelle maintenant « Create and publish games and places », et l'ancienne URL redirige). Les menus de Studio cités (« Experience Settings », « Publish Experience ») pourraient être renommés. D'autres modules utilisent peut-être encore l'ancienne URL (redirection fonctionnelle, mais à surveiller lors de la prochaine mise à jour).
4. **Longueur** : la leçon 04.02 dépasse 5 000 mots (code compris), bien au-delà des 900 à 1 800 mots indiqués dans AUTHORING. Je n'ai rien supprimé, car tout est utile. Une découpe en deux leçons (« Sauvegarde fiable » / « Limites, versions et verrouillage ») allégerait le module 04, mais elle toucherait PLAN.md et `modules.ts`, donc la décision revient au chef d'orchestre.
5. **Pluriel « obbies »** : il reste dans `module-00/03-mindset-du-createur.mdx` et `module-01/05-premier-niveau-et-publication.mdx`, alors que les autres modules écrivent « obbys ». Ces fichiers sont hors de mon périmètre.
6. **06.04, script `Abonnements` et bouton `BoutonNuagePlus`** : ils sont présentés comme optionnels (« imaginons ») et absents de `projet-reference`, ce qui est cohérent. En revanche, l'emplacement du bouton dans l'interface n'est pas précisé : à ajouter si l'abonnement devient un jour une étape obligatoire du fil rouge.
7. **Remarques déjà signalées dans les leçons, que j'ai laissées en l'état** : la mise en vente d'un pass n'est plus détaillée par la documentation (06.02). La simulation des achats dans Studio repose sur une annonce de 2016 (06.03). `ProcessReceipt` ne serait pas appelé en Team Test d'après un rapport du DevForum (06.03). Les plateformes tweenées n'emportent pas le personnage d'après des retours du DevForum (04.06). Les textes les présentent honnêtement comme non officiels ou anciens.
8. **Code Luau** : je n'ai relevé aucune erreur. Le comportement « expulsion à chaque test si l'accès aux API n'est pas activé » (`GestionJoueurs`) est voulu et expliqué. C'est toutefois le premier piège dans lequel un débutant tombera : un encadré `<Erreur>` dédié en 04.02 pourrait être utile (la phrase existe déjà dans la section « Activer l'accès dans Studio »).
